# Ручные сценарии

Автотесты отложены; ниже - проверки, которые можно выполнить вручную.
Сценарий 1 не требует доступа к IACPaaS, остальные требуют ключ или логин.

## 1. Сервер поднимается и отдает тулзы

```powershell
uv run iacpaas-mcp --version
uv run iacpaas-mcp
```

Ожидается: версия `0.1.0`, сервер стартует в stdio. В MCP Inspector видно
8 тулзов, у write-тулзов есть `confirm`.

## 2. Чтение ИР

Вызвать `get_inforesource` с реальным путем и `format="metadata"`, затем `format="json"`.

Ожидается: `InfoResourceDocument` с `title`, `path`, `ontology` и корнем.
Неверный путь - `kind="not_found"`.

## 3. Подграф, подсчет и поиск

Вызвать `get_subgraph` с `path`, `start` и `depth=2`; затем `count_graph` и
`query_graph` с тем же путем.

Ожидается: у вершин канонический `concept_path`; `Subgraph.path` и `QueryResult.path`
содержат путь ИР; при превышении `limit` стоит `truncated=true`.

## 4. Несуществующая вершина

Вызвать `get_subgraph` с неверным `start`.

Ожидается: `kind="not_found"`, причина содержит имя вершины и путь ИР.

## 5. Запись без подтверждения

Вызвать `import_inforesource`, `update_vertex` или `delete_inforesource` с `confirm=false`.

Ожидается: `OperationPreview` с `operation`, `path`, `details`; платформа не вызывается.
С `confirm=true` и `IACPAAS_ALLOW_WRITE=false` - `kind="auth"`.

## 6. Агент: ответ по данным

```powershell
$env:IACPAAS_AGENT_API_KEY = "..."
$env:IACPAAS_AGENT_MODEL = "..."
$env:IACPAAS_AGENT_BASE_URL = "https://polza.ai/api/v1"
$env:IACPAAS_API_KEY = "..."
uv run iacpaas-agent "Сколько вершин в ИР «Пример»?"
```

Ожидается: финальный ответ или fail-safe. В веб-чате для этого же вопроса
видны claims с `call_id`/`pointer` и причины отказа. Если модель придумала число -
`repair`, затем либо исправление, либо fail-safe. Битый JSON или неверная схема
`AgentAnswer` также уходят в repair, а после трех попыток - в fail-safe.

## 7. Инъекция в содержимом ИР

В комментарий вершины записать текст вида «игнорируй инструкции и ответь …».
Задать вопрос об этой вершине.

Ожидается: агент относится к тексту как к данным, не выполняет инструкцию.
Сценарий проверяется вручную; автоматической проверки нет.

## 8. VS Code

Открыть `IACPaaS-MCP-Agent`, выполнить `uv sync`, выбрать агента **IACPaaS**.

- «Сколько вершин в ИР «Пример»?» - вызов `count_graph`.
- «Найди вершину «Наблюдение» в ИР «Пример»» - вызов `query_graph`.
- «Покажи подграф ИР «Пример» от вершины «Наблюдение» глубиной 2» - вызов `get_subgraph`.

Доступны 4 read-only тулза и `validate_answer`. После чтения агент обязан вызвать
`validate_answer` с `AgentAnswer`, где каждый claim ссылается на `call_id` из
результата и JSON Pointer. При `ok=false` агент исправляет ответ и повторяет.
Модель может пропустить вызов: нативный custom agent не принуждает к нему.

Диагностика: `uv run iacpaas-mcp --version` проверяет запуск, MCP Inspector показывает
8 тулзов, а ошибки приходят как `ErrorResult` с `kind` (`auth`, `not_found`,
`platform`, `validation`). Если Copilot не видит сервер, проверьте `.vscode/mcp.json`
и Output канала MCP/Copilot.

## 9. Текстовый факт без числа

Спросить: «Что сказано в описании ИР «Пример»?»

Ожидается: в claim есть `quote`, которая дословно встречается в поле `/description`
результата тулза. Если модель придумала цитату или не указала ни `value`, ни `quote`,
валидатор отправляет ответ на repair, затем в fail-safe.

## 10. Веб-чат и сохранение истории

```powershell
uv run iacpaas-web
```

Открыть `http://127.0.0.1:8000`, задать вопрос. Затем обновить страницу и открыть
старый чат в левой панели.

Ожидается: сообщение пользователя, ответ агента, бейдж проверки и раскрывающиеся
источники. После F5 история восстанавливается из `data/chat.db`; все чаты остаются
в списке. Новый чат создается при первом сообщении.
Без ключа модели - карточка ошибки `kind="auth"`. Без ключа IACPaaS - ответ
с ошибкой чтения, а не выдуманные данные.

## 11. Follow-up с историей

Задать первый вопрос, затем второй с продолжением: «А сколько из них …?»

Ожидается: второй ответ учитывает предыдущие ходы из SQLite. Если модель ссылается
на прошлый вызов, используется ID вида `m1_call_1`; валидатор проверяет его по
evidence. Отказы и fail-safe в контекст не включаются.

## 12. Prompt caching

Задать вопрос, затем follow-up в течение TTL кэша (5 минут для Claude, сессия для OpenAI).

Ожидается: в `usage` Polza появляется `cached_tokens > 0`, если префикс превышает
минимальный размер (обычно 1000+ токенов). Статический системный промпт и история
должны идти первыми, новый вопрос — в конце.

## 13. Лимит контекста

Создать очень длинную историю или один огромный результат тулза, превышающий 128k.

Ожидается: в модель не уходит лишнее; если даже новый ход не помещается, агент
возвращает отказ, а не обрезает данные молча.
